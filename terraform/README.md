# FixBoard platform (Terraform)

This code builds the platform FixBoard runs on: network, EKS cluster, container registry, database, shared storage, secrets, and the cluster add-ons. In the course story the Platform Engineering team owns it. You run it once in your own AWS account, then work on the application and the delivery around it.

It is one project in three phases, controlled from a single `platform/terraform.tfvars` file, which you create from `terraform.tfvars.example`.

| Phase | What it adds | Switch |
|---|---|---|
| 1. Application deployment | Network, EKS, ECR, RDS, EFS, secrets, ALB controller, EFS CSI, External Secrets Operator, metrics-server, ExternalDNS | always on |
| 2. CI/CD and GitOps | GitHub Actions role for ECR push, ArgoCD | `enable_gitops = true` |
| 3. Observability and operations | Prometheus, Alertmanager, Grafana, Fluent Bit to CloudWatch | `enable_observability = true` |

## Before you start

Installed on your machine: Terraform 1.6 or later, AWS CLI v2, kubectl.

Already in the AWS account, in the region you deploy to:

- A public Route 53 hosted zone for your domain.
- An ACM certificate in status `ISSUED` that covers your domain. Use its primary domain name for `certificate_domain` (for example `*.example.com`).

The plan fails early with a clear message if either one is missing.

## Run it

```bash
cd terraform/platform
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars: domain_name and certificate_domain
terraform init
terraform plan -out=tfplan
terraform apply tfplan
```

Read the plan before you apply it. `terraform.tfvars`, the state file and saved plans are ignored by Git and must stay out of the repository: the state holds the generated database password and JWT secret in plain text. Commit `.terraform.lock.hcl` so everyone installs the same provider versions.

The first apply takes a while, mostly the EKS control plane and the database. When it finishes:

```bash
terraform output kubeconfig_command   # run the command it prints
kubectl get nodes
```

### Moving to Phase 2 and 3

Edit `terraform.tfvars`, run `terraform plan -out=tfplan`, review it, then `terraform apply tfplan`. Only the new pieces are created.

```hcl
enable_gitops        = true
github_repository    = "your-org/fixboard"

enable_observability = true
```

If your account already has the GitHub OIDC provider (only one is allowed per account), also set `create_github_oidc_provider = false`.

## What the application team receives

Run `terraform output` for the full list. The values the application needs:

| Output | Used for |
|---|---|
| `ecr_repository_urls` | Where images are pushed |
| `rds_endpoint` | Target of the ExternalName Service |
| `storage_class_name` | `storageClassName` of the uploads claim (ReadWriteMany) |
| `cluster_secret_store_name` | `secretStoreRef` in an ExternalSecret |
| `certificate_arn` | `alb.ingress.kubernetes.io/certificate-arn` on the Ingress |
| `github_actions_role_arn` | `role-to-assume` in the workflow (Phase 2) |

### Secrets in AWS Secrets Manager

| Secret | Keys |
|---|---|
| `fixboard/db-credentials` | `username`, `password`, `dbname`, `host`, `port` |
| `fixboard/backend-secrets` | `JWT_SECRET` (generated by Terraform, never typed by hand) |

The External Secrets Operator can read both. Hosts used on an Ingress are published to Route 53 automatically by ExternalDNS, for the domain you configured.

## Tear down

Kubernetes creates some AWS resources that Terraform does not know about. Remove them first or the VPC cannot be deleted.

1. Delete everything that created a load balancer: uninstall the app release, delete any remaining Ingress objects, and (Phase 2) delete the ArgoCD applications. Wait until the load balancers are gone in the EC2 console.
2. `terraform destroy` in `platform/`.
3. Keep `platform/terraform.tfstate` until the destroy finishes. It lives on your machine and is the only record of what was built.

## Design notes and trade-offs

- **State is local.** Terraform keeps its state in `platform/terraform.tfstate` on your machine. It contains secrets, so never commit it. Do not delete it, and back it up if you cannot afford to lose the environment. A remote backend such as S3 is a natural next step for a team.
- **Teaching environment defaults.** Single NAT gateway, single-AZ database, no final snapshot, no deletion protection, secrets deleted immediately on destroy. Change these before reusing the code for anything real.
- **Database TLS is not enforced** (`rds.force_ssl = 0`) because the application connects without TLS. A production setup keeps it on and ships the RDS CA bundle with the app.
- **Public Kubernetes API.** `api_public_access_cidrs` defaults to everywhere so students can reach it from any network. Narrow it to your own IP when you can.
- **Helm chart versions are unpinned** (latest). After a working apply, pin them in `chart_versions` so reruns are repeatable.
- **Prometheus has no persistent volume.** Metrics are lost when its pod restarts. Adding the EBS CSI driver and a volume is a natural extension.
- **Kubernetes version** defaults to 1.35. Check the EKS version calendar before changing it; versions past standard support cost more.
- **Node scaling is out of scope.** The Horizontal Pod Autoscaler scales pods; the node group is fixed at 2 to 4 nodes.
